**Engine** is what answered; **requested engine** is what this box was told to
run. They differ while a change is reconciling, and they differ *persistently*
when the requested engine will not start — which is the case worth seeing, since
a box that quietly kept running the old one would look like a change that
worked.

To swap engines, edit `desired.engine` in this document's literal JSON and then
restart the engine below. A box runs one at a time: two would contend for the
same GPU and the same port, and "which one served this request" is not a
question these documents could answer honestly.

## Model

The engine reconciles toward the requested model. To change it, open this
document's literal JSON and edit the `desired` block — the view shows state and
runs controls, it has no editable fields of its own. That edit enters the same
admission path as the controls below.

A box holds the models it was told to hold. Adding an id and applying fetches
it; removing one does not delete anything — the model becomes `orphaned` and
waits for a prune, because a list is a poor place to lose several hundred
gigabytes to a typo.

## Throughput

There is no queue. The engine admits up to its concurrency limit and rejects
beyond it, so a rising rejection count means the box is under-sized rather than
merely busy — latency stays honest instead of absorbing the overload silently.
